# 李老汉窑烤面包品牌官网

前后端分离项目：`frontend` 为 Nuxt 3 动态官网，`backend` 为全中文 Strapi 5 内容后台。

## 本地开发

1. 为 PostgreSQL 创建数据库 `lilaohan`。
2. 分别复制 `frontend/.env.example` 与 `backend/.env.example` 为 `.env`，填写真实配置。
3. 在 `backend` 运行 `npm run develop`，首次访问 `http://localhost:1337/admin` 创建管理员。
4. 后台会自动创建“内容编辑”角色，并为公开访问角色配置只读内容权限。
5. 在 `frontend` 运行 `npm run dev`，访问 `http://localhost:3000`。

开发环境带有一套明确标注的兜底内容，便于 Strapi 未启动时预览。生产环境不会在菜单为空时回填演示产品。正式上线前应在后台补齐真实门牌、营业时间、电话、微信、地图链接、产品价格、镇山村点位与实拍图片。

## 中文后台的日常操作

- 访问 `http://localhost:1337/admin`，登录后界面默认显示简体中文。
- 在“产品分类”和“菜单产品”中维护窑烤菜单；内容需要点击“发布”后才会显示在官网。
- 在“官网与照片设置”中替换首页、菜单、DIY和打卡指南主图，也可维护微信号、上传微信二维码和填写小红书到店指引链接。到店页二维码支持点击放大，小红书指引以新窗口打开。
- 到店页首屏主按钮固定显示“到店指引”，直接打开“官网与照片设置”中的小红书到店指引链接，不再使用高德地图导航作为首屏主按钮。
- 在“手作体验设置”中维护每人面团、成品数量、预约赠品和主推教程。每个项目的价格在“手作体验”中的“详情页价格”维护，仅对应项目详情页展示；首页和项目目录不读取价格。面包 DIY 当前为 78 元 / 人，披萨 DIY 当前为 98 元 / 人。
- 在“页面板块”中修改各页面固定板块的中文标题、说明、按钮和配图。系统会自动生成这些板块；“板块编号”和“所属页面”是前端连接字段，请不要修改或删除。
- 截图中的橙色联系区说明在“全站联系引导”的“展示文字 / 简短说明”中修改；底部品牌说明在“全站页脚品牌介绍”的同名字段中修改。留空时橙色联系区会使用官网设置里的地址、营业时间和停车提示。
- 首页推荐产品、手作项目、打卡机位、品牌故事和常见问题仍在各自内容栏目维护，发布后会与“页面板块”的标题和配图组合显示。
- 首页“刚出炉的味道”展示品类卡片，不显示单品价格；在“首页·招牌菜单”的“板块小项 / 品类卡片”中维护名称、介绍、图片和链接。完整菜单页仍展示单品及参考价格。
- 每张首页品类卡片可选择“代表产品”，首页优先使用该产品的图片；没有合适产品时再上传“备用图片”。围炉煮茶目前需要上传真实备用图片，或新增对应菜单产品后再关联。
- 首页品类卡片使用“完整主体图＋柔化背景”显示方式，上传横图或竖图都不会被卡片文字区域裁掉；需要调整构图时直接在后台替换代表产品图或备用图即可。
- 菜单产品卡片和产品详情同样使用完整主体图显示，横图与竖图都不会被固定卡片比例裁掉；菜单顶部氛围主图仍保持铺满展示。
- 图片说明统一在媒体库的“替代文字”中维护；该文字用于搜索引擎和无障碍阅读，不会直接显示在页面上。
- 大尺寸 PNG 上传后，后台会自动生成 480px 和 800px 的轻量 WebP 响应图；教程和官网前端优先加载 WebP，原图继续保留在媒体库。已有大图会在后台启动时自动补齐优化版本。
- 在“手作体验”中维护体验状态、步骤图片、配料与工具的名称及真实照片，以及演示视频链接。教程封面可暂时留空，视频链接必须以 `https://` 开头。
- `/diy` 使用杂志式拼贴展示所有已发布项目：主推项目占据左侧大卡片，其他项目在右侧和下方自动排列；手机端先显示全部项目名称索引。点击卡片进入项目介绍，有真实步骤且状态为“开放体验”时才显示“查看教程”。目录标题、说明和空状态在“页面板块”中维护。
- 手作体验目录固定优先展示：面包 DIY、披萨 DIY、饼干 DIY、蜡染 DIY；后续项目按后台“显示顺序”继续排列。
- 饼干 DIY 与蜡染 DIY 首版标记为“内容筹备中”，只展示已确认的名称和微信咨询入口；后台补齐真实流程并切换为“开放体验”后，教程入口才会出现。
- 面包 DIY 教程使用“章节式教程”维护，默认包括窑炉科普、工具使用和面包造型三章；每章可增删课程，并为课程维护图片、操作步骤和安全提示。披萨等旧教程继续兼容原有“体验步骤”。
- 黑窑与白窑按燃烧烟气是否直接经过烘烤室区分，并非按窑炉外观颜色区分。默认科普内容参考 [Masonry Heater Association 的烘焙窑炉资料](https://www.mha-net.org/docs/admin/BakeOvenPort.pdf)，不用于判断门店窑炉的具体类型。
- 面包体验详情聚焦价格、面团份量、准备工作、七步流程、配料、工具、创作理念和微信预约；未上传真实照片时前端显示品牌占位，不使用随机网络图片。
- 手作体验仅通过添加门店微信预约；弹窗读取后台微信号和二维码，二维码可点击放大，不提供电话预约按钮。
- “今日同炉”已升级为店员登记的“出炉进度”系统。店员从后台左侧独立入口登记顾客姓名、联系电话和可选入炉照，保存后立即开始默认 90 分钟倒计时。
- 店员可在“出炉进度”工作台查看每位顾客的实时进度，提前或延后预计完成时间，标记“可以取啦 / 已领取 / 已取消”，并补充入炉前或出炉后照片。
- 顾客打开 `/oven/today`，只需输入登记手机号后四位即可查询自己的进度；查询使用 POST，页面不会公开顾客名单，也不会返回完整手机号、校验摘要或其他顾客记录。
- 为避免尾号相同导致查错，系统不允许同时存在两个手机号后四位相同的“制作中 / 可以取啦”记录。若现场出现相同尾号，店员需先完成上一条记录，或为顾客提供人工查询。
- 旧版炉次与作品链接继续作为只读历史保留；顾客投稿、添柴和自行补图接口已经停用。新的公开接口只有受限查询 `POST /api/oven/orders/lookup`。
- 订单达到预计时间后自动切换为“可以取啦”。后台每分钟同步状态，接口查询时也会校准；完成、领取或取消 30 天后自动清除可解密的完整电话，仅保留后四位与不可逆校验摘要供历史查询。
- 进度照片复用 Strapi 媒体库，入炉照与出炉照均可为空；后台选择超过 4MB 的 JPG、PNG 或 WebP 照片时会自动缩放并压缩为适合网页的 JPEG，再上传到保留 5MB 安全上限的服务端。不要向公开角色开放 Strapi 通用上传或出炉进度内容类型的写权限。
- 在“官网与照片设置”中可替换网站头像与品牌图标。
- 店员账号应分配“内容编辑”角色，不要分配超级管理员角色。

## 动态部署

- 主页微信访问二维码下载页为 `/qr/home`，二维码文件为 `/images/homepage-qr-ip-v1.png` 和 `/images/homepage-qr-ip-v1.svg`。当前文件只用于 `http://122.51.118.103/` 的 IP 验收。
- 面包进度查询二维码下载页为 `/qr/oven`，二维码指向 `/oven/today`；高清文件为 `/images/oven-progress-qr-ip-v1.png` 和 `/images/oven-progress-qr-ip-v1.svg`。
- 重新生成二维码时，在 `frontend` 运行 `npm run generate:homepage-qr`；可通过 `HOMEPAGE_QR_URL` 与 `HOMEPAGE_QR_VERSION` 指定新地址和新版本。绑定备案域名并启用 HTTPS 后必须使用新版本文件名，避免一年期图片缓存和已印刷旧地址混淆。

- 复制 `deploy/.env.example` 为 `deploy/.env`，填写域名、数据库密码和随机密钥。
- 为出炉进度中的完整电话设置 `OVEN_PHONE_ENCRYPTION_KEY`，必须使用至少 32 位的独立高强度随机值且不得提交。旧版历史数据仍可能读取 `OVEN_OWNER_TOKEN_SECRET`、`OVEN_ANONYMOUS_ID_SALT`，新流程不再使用它们进行投稿或添柴。
- 运行 `docker compose --env-file deploy/.env up -d --build`，启动 Nuxt、Strapi、PostgreSQL 和 Caddy。
- Caddy 将 `/api` 和 `/uploads` 转发到 Strapi，其余页面转发到 Nuxt；后台发布后官网会在下一次访问时读取新内容。
- IP 验收阶段按店主要求临时开放 `http://服务器IP/admin`，Caddy 只通过 80 端口代理后台及其内容管理、媒体上传等必要接口；Strapi 的 `1337` 仍仅绑定服务器环回地址。当前 HTTP 后台不加密登录密码和令牌，不适合长期使用；绑定域名后应立即改为独立 HTTPS 后台域名并重新限制访问来源。
- 如需紧急关闭公网后台，将 `deploy/Caddyfile` 中的 `@strapiAdmin` 代理恢复为 `handle /admin* { respond "Not Found" 404 }` 并重载 Caddy，之后继续通过 SSH 隧道访问。
- 上传文件默认保存在 Docker 数据卷中；正式长期运行建议接入阿里云 OSS 或腾讯云 COS，并做好数据库与上传目录备份。
- 中国大陆公开网站上线前完成域名实名认证、ICP备案及必要的公安备案。

现有 ChatGPT Sites 地址继续作为静态临时版本，不使用当前动态构建覆盖。正式服务器验收完成后再切换域名。
